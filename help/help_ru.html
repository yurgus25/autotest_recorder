Группы тестов

Группы помогают собрать несколько связанных тестов в один повторно используемый блок и запускать их одним кликом.

🧩 Создайте группу в popup и выберите цвет. Цвет используется для подложки и тени группы, чтобы визуально разделять разные бизнес‑сценарии.
🧩 В группу Кнопка на карточке одиночного теста — добавляет тест в уже существующую группу. Один и тот же тест можно переиспользовать в нескольких группах без копирования шагов.
▶️ Запуск группы Запускает все тесты внутри группы по порядку. Удобно собирать длинные пользовательские сценарии из маленьких тестов (логин → действия → логаут).
●●●▶️ Иконка с тремя красными точками перед ▶️ на кнопке группы показывает суммарное количество маркеров записи во всех вложенных тестах (до трёх точек). Можно сразу видеть, где во время прогона будет предложено дозаписать шаги.
💾 / ✏️ / 🗑️ Экспорт всей группы в JSON, редактирование названия и цвета группы, удаление группы (сами тесты в списке не удаляются).

С помощью групп вы можете держать тесты маленькими и понятными, но при этом запускать длинные пользовательские сценарии одним кликом и переиспользовать одинаковые части (логин, навигация, логаут) в разных группах.

🔍 Расширенный поиск селекторов и инспектор селекторов

Два инструмента помогают находить и проверять селекторы для элементов страницы: расширенный поиск (отдельная страница со списком всех элементов вкладки) и инспектор селекторов (панель поверх страницы с подсветкой при наведении).

Расширенный поиск селекторов

Открывается кнопкой 🔍 Расширенный поиск селекторов в шапке popup (или в строке под заголовком в полноэкранном режиме). Открывается отдельная вкладка с анализатором.

  • Выбор вкладки: вверху страницы в выпадающем списке Вкладка отображаются все открытые вкладки. Можно выбрать любую вкладку — анализ селекторов выполняется для выбранной страницы.
  • Анализ: на странице перечисляются кнопки, поля ввода, ссылки, выпадающие списки и другие интерактивные элементы. Для каждого показываются варианты селекторов (data-testid, id, классы, Finder Lite, Unique Selector и др.), приоритет и признак уникальности.
  • Вкладки результатов: «Все элементы», «Dropdown», «Статус», «Опции dropdown» — фильтр по типу элементов.
  • Фильтры и поиск: чекбоксы (кнопки, поля, списки, ссылки, dropdown) и строка поиска по тексту или селектору.
  • Копирование: у каждого варианта селектора есть кнопка 📋 Копировать — скопированный селектор можно вставить в шаг теста в редакторе.
  • Обновить: кнопка 🔄 Обновить повторно запускает анализ выбранной вкладки. 📥 Экспорт JSON сохраняет полный отчёт в файл.

Инспектор селекторов

Включается кнопкой 🔍 (инспектор) в шапке popup. На текущей вкладке появляется плавающая панель, а при наведении курсора на элемент страницы он подсвечивается и в панели показываются сгенерированные селекторы.

  • Как пользоваться: откройте нужную страницу, включите инспектор из popup. Наводите курсор на элементы — в панели отображаются тег, текст, атрибуты и список селекторов с пометками «Лучший» и «Уникальный». Кнопки 📋 Копировать и ✓ Тест позволяют скопировать селектор или проверить его на странице.
  • Фиксация селектора: чтобы закрепить панель на одном элементе и спокойно скопировать нужный селектор, удерживайте указатель на элементе около 2 секунд (не отпуская кнопку мыши). После этого элемент считается зафиксированным: список селекторов в панели не меняется при движении курсора, подсказка меняется на «✓ Элемент зафиксирован. Кликните вне окна для снятия фиксации.» Чтобы снять фиксацию, кликните по странице вне панели инспектора (например, по пустому месту или по другому элементу). После этого снова можно наводить курсор на другие элементы.
  • Закрытие: кнопка ✕ в панели закрывает инспектор. Кнопка ← возвращает в popup.
💡 Совет: используйте расширенный поиск, когда нужно получить список всех селекторов на странице или выбрать вкладку для анализа. Инспектор удобен для быстрой проверки одного элемента и фиксации селектора перед вставкой в шаг теста.

Запись тестов

Расширение фиксирует: клики, ввод текста, выбор из <select> и кастомных dropdown, переходы, навигацию.

Маркеры записи

Маркер записи — специальный шаг, который при прогоне ставит тест на паузу и запускает короткую дополнительную запись прямо посреди сценария. В один тест можно добавить несколько маркеров и при каждом прогоне дозаписывать новые действия ровно там, где они нужны.

  • Когда воспроизведение доходит до маркера, тест приостанавливается и для текущего теста запускается запись.
  • Выполните дополнительные действия на странице, затем остановите запись в popup:
  • ⏹️ Остановить запись (красная кнопка) — сохраняет новые шаги после маркера и снимает сам маркер.
  • ⏹️ Стоп (серая кнопка) — отменяет запись по маркеру: новые шаги отбрасываются, маркер остаётся на месте, воспроизведение останавливается.
  • После обычной остановки сценарий продолжается с шага сразу после маркера так, как будто новые шаги изначально были частью теста.

Режимы выбора селекторов

Настраиваются в ⚙️ → Режим записи:

Автоматический

Расширение само выбирает лучший селектор по приоритетам атрибутов. Подходит для большинства случаев.

Пикер

При каждом клике показывается панель с вариантами селекторов — вы выбираете нужный.

Инспектор

Полный инспектор элемента с детальным анализом всех доступных селекторов.

Для генерации используются библиотеки Finder, Optimal Select и Unique Select (включаются в настройках, для каждой есть версия Lite/Full).

💡 Совет: Перед записью обновите страницу. Действуйте без спешки — расширение фиксирует каждый клик. Используйте маркеры записи, чтобы итеративно наращивать длинные сценарии: сначала запишите «скелет», затем при каждом прогоне дозаписывайте недостающие детали в нужных местах.

Редактор тестов

Открывается кнопкой ✏️ Редактировать в карточке теста.

Открытие и создание тестов

  • Редактирование существующего теста — нажмите ✏️ Редактировать на карточке в popup.
  • Создание из записи — запишите новый тест через popup; при переходе в редактор откроются записанные шаги.
  • Дублирование через «Сохранить как…» — в редакторе используйте кнопку 💾 Сохранить как…, чтобы создать копию с новым именем и ID (оригинальный тест не изменяется).
  • Импорт как нового теста — в редакторе нажмите 📤 Импорт JSON; импортированные данные сохраняются как отдельный тест, который тут же откроется в редакторе.

Пример настройки шага «Скриншот»:

Шаги «Анализ»

Шаги анализа помогают автоматически разобрать страницу, селекторы и производительность, не просматривая руками каждый элемент.

Как добавить

  • Откройте тест в редакторе → нажмите ⚡ Быстрые шаги → группу 🔍 Аналитика.
  • Выберите нужный шаблон: Селекторы, Заполнить поля, Валидация, Формы, Ссылки, Производительность.
  • При необходимости задайте целевой URL / селектор / область действия — в зависимости от шаблона.
Анализ → Селекторы Сканирует страницу, генерирует несколько вариантов селекторов для важных элементов и оценивает их стабильность. Результаты доступны в редакторе — можно быстро выбрать и применить лучший селектор.
Анализ → Заполнить поля Находит формы и поля ввода на странице и автоматически строит шаги для их заполнения тестовыми данными (можно использовать переменные). Удобно для быстрого создания сценария по новой форме.
Анализ → Валидация Добавляет проверки сообщений валидации и важных состояний UI (например, «поле обязательно», «отображается сообщение об успехе»). Ускоряет превращение ручных проверок в стабильные автотесты.
Анализ → Формы Строит структурированный обзор форм на странице (поля, подписи, плейсхолдеры) и помогает сгенерировать набор шагов для работы с формой (заполнить, очистить, проверить).
Анализ → Ссылки Собирает все ссылки, кнопки и навигационные элементы на странице, проверяет, что к ним можно обратиться по селекторам и при необходимости создаёт проверки.
Анализ → Производительность Измеряет Web Vitals (LCP, CLS, INP, TTFB) и загрузку ресурсов в процессе выполнения теста. Результаты отображаются в Performance Dashboard и в детальном отчёте по ресурсам (время, размер, на каком шаге был загружен ресурс) и могут сравниваться с baseline‑значениями.

Отчёт по результатам

После выполнения шагов «Анализ» из редактора можно открыть подробный отчёт:

  • Селекторы / Формы / Ссылки — структурированный список элементов с сгенерированными селекторами, оценкой стабильности и подсказками, что стоит поправить или покрыть тестами.
  • Валидация — перечень найденных сообщений и предлагаемых проверок.
  • Производительность — графики Web Vitals, таблица ресурсов (имя, тип, размер, длительность, шаг), сравнение с baseline.

Адаптивный шаг

Адаптивные шаги стоит применять, когда нужно быстро сделать сценарий устойчивым к разным вариантам верстки (A/B‑тесты, feature‑флаги, мелкие правки) или когда достаточно «просто заполнить все видимые поля случайными, но валидными значениями» без ручной настройки каждого селектора.

Особенности настройки

  • Целевая область — обычно селектор контейнера (форма, модальное окно, карточка). Адаптивная логика ищет поля и кнопки только внутри этой области.
  • Стратегии — можно выбрать приоритет: максимально стабильные селекторы (data-testid и т.п.) или максимально короткие. Для простого заполнения всех полей достаточно дефолтных настроек.
  • Типы полей — для текстов, чисел, дат, select и checkbox генератор подбирает значения, которые выглядят валидно (email, телефон, даты в допустимом диапазоне, существующие опции).
  • Исключения — можно указать селекторы, которые нужно пропустить (например, поисковая строка или кнопки с разрушительными действиями).
Adaptive → Single Описывает несколько альтернативных селекторов или действий для одного логического шага. Во время прогона AutoTest Recorder по очереди пробует варианты и использует первый успешно сработавший.
Adaptive → Auto Автоматически «учится» по успешным прогонам: когда селекторы были подлечены или изменены, адаптивная логика запоминает альтернативы и может использовать их в будущих запусках.
Adaptive → Flow Описывает целый мини‑флоу (например, логин) с несколькими возможными ветками. При выполнении движок выбирает ту ветку, которая подходит под текущую версию интерфейса.
💡 Совет: Используйте шаги «Анализ» для быстрого наброска логики теста на новой странице, а «Адаптивный» — чтобы тесты переживали изменения верстки и фич‑флагов.

Доступные действия (краткий справочник)

В редакторе доступно много типов действий, которые можно добавлять через ➕ Добавить и меню ⚡ Быстрые шаги.

Навигация и прокрутка

  • Навигация — открыть URL, обновить страницу, назад/вперёд в истории, получить текущий URL.
  • Вкладки — открыть новую вкладку, переключиться между вкладками, закрыть вкладку.
  • Прокрутка — к элементу, в начало, в конец страницы.

Взаимодействие с элементами

  • Клики — клик, двойной клик, правый клик, фокус/blur, наведение (hover).
  • Выпадающие списки — выбор опции, мультивыбор, очистка, выбрать все, инверсия выбора, копировать/вставить опции, изменить порядок.
  • Ввод — ввод текста, очистка поля, нажатие клавиши, загрузка файла.

Переменные и буфер обмена

  • Переменные — установить значение, получить из элемента или URL, собрать строку, работать со значениями из localStorage.
  • Буфер обмена — скопировать текст из элемента, вставить в элемент, прочитать/записать буфер через переменную.

Ожидания и проверки

  • Ожидания — пока элемент станет видимым/скрытым, появится/исчезнет в DOM, пока появится опция, нужное значение или выполнится JS‑условие.
  • Проверки — видимость/скрыт, существует/отсутствует, текст/значение содержит, количество элементов, состояние disabled/enabled, содержимое multiselect.

Таблицы, даты и Drag & Drop

  • Таблицы — получить значение ячейки/строки/столбца, кликнуть по ячейке, проверить количество строк/столбцов, найти строку по тексту.
  • Дата‑пикер — выбрать дату/диапазон/время, очистить, открыть/закрыть календарь.
  • Drag & Drop — перетащить на элемент, по смещению, в координаты, шаги start/over/drop.

Медиа, сеть и скриншоты

  • Медиа — play/pause/stop, перемотка, громкость и скорость, fullscreen / выйти из fullscreen.
  • Сеть — ждать запрос, ждать простоя сети, проверять факт запроса и статус ответа.
  • Скриншоты — скриншот элемента, всей страницы (с прокруткой).

Устройство, JavaScript и обработка ошибок

  • Устройство — смена размера viewport, эмуляция мобильного/планшета/десктопа.
  • JavaScript — выполнение произвольного JS‑кода в контексте страницы и сохранение результата в переменную.
  • Try‑catch — группировка шагов с обработкой ошибок и кастомным fallback.
  • Cookies — установка и чтение cookie.

Действия, помеченные в редакторе как «скоро» или «PRO», заблокированы и не выполняются — в этом разделе перечислены только доступные в текущей версии действия.

⚡ Аналитика производительности

Performance Analytics — система мониторинга производительности веб-приложений, интегрированная в AutoTest Recorder. Собирает Web Vitals метрики, детали загрузки ресурсов и позволяет отслеживать изменения производительности.

📊 Как использовать

Шаг 1: Добавьте шаг анализа производительности

  1. Откройте тест в редакторе
  2. Нажмите + Вставить шаг
  3. Выберите Analysis → Performance

  • Нажмите ▶️ Полный прогон или ⚡ Оптимизированный

  • Будут собраны метрики на каждом шаге теста

Шаг 3: Просмотрите отчёт

  • После выполнения теста в редакторе появится кнопка 📊 Посмотреть отчёт производительности
  • Кликните на кнопку — откроется Performance Dashboard
  • Или откройте консоль браузера и скопируйте ссылку на dashboard

📈 Web Vitals метрики

LCP (Largest Contentful Paint) — время до отрисовки основного контента

  • ✅ Хорошо: ≤ 2.5 секунды
  • ⚠️ Требует улучшения: 2.5с - 4с
  • ❌ Плохо: > 4 секунды

CLS (Cumulative Layout Shift) — смещение элементов при загрузке

  • ✅ Хорошо: ≤ 0.1
  • ⚠️ Требует улучшения: 0.1 - 0.25
  • ❌ Плохо: > 0.25

INP (Interaction to Next Paint) — время отклика на взаимодействие

  • ✅ Хорошо: ≤ 200 мс
  • ⚠️ Требует улучшения: 200мс - 500мс
  • ❌ Плохо: > 500 мс

TTFB (Time to First Byte) — время до первого байта от сервера

  • ✅ Хорошо: ≤ 800 мс
  • ⚠️ Требует улучшения: 800мс - 1800мс
  • ❌ Плохо: > 1800 мс

🗂️ Базовые линии (Baselines)

Сохранение baseline:

  1. Откройте Performance Dashboard после успешного теста
  2. Нажмите 💾 Сохранить базовую линию
  3. Введите название (например, "Production v1.0")
  4. Baseline сохранён (хранится до 10 последних для каждого теста)

Сравнение с baseline:

  3. Нажмите 📂 Загрузить базовую линию
  4. Выберите нужный baseline из списка
  5. Визуальное сравнение будет доступно в Phase 2

  • Обращайте внимание на Web Vitals — они влияют на SEO и UX

  • Экспортируйте данные — сохраняйте JSON для отчётов и CI/CD

🚨 Частые вопросы

Q: Кнопка "Посмотреть отчёт" не появляется?

A: Убедитесь что тест содержит шаг analysis-performance и был запущен хотя бы один раз.

Q: Web Vitals показывают null или 0?

A: Некоторые браузеры (Firefox, Safari) имеют ограниченную поддержку Web Vitals API. Используйте Chrome/Edge для полной функциональности.

Q: Почему много ресурсов на шагах 0-2?

A: Это нормально! Первые шаги теста обычно содержат начальную загрузку страницы (HTML, CSS, JS, изображения). Последующие шаги загружают меньше ресурсов.

Q: Можно ли использовать для CI/CD?

A: Да! Экспортируйте данные в JSON и интегрируйте проверки в pipeline. Phase 2 добавит автоматическое определение регрессий.

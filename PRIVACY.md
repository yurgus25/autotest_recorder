# Политика конфиденциальности и обоснование разрешений (Chrome Web Store)

**Русский** | [English](PRIVACY_EN.md)

Документ предназначен для раздела **«Конфиденциальность»** в [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole/) и для согласования текста **краткого описания** и **подробного описания** расширения с фактическим поведением. Сайт [developer.chrome.com](https://developer.chrome.com/) публикует [требования к программе](https://developer.chrome.com/docs/webstore/program-policies/) и [данным пользователя](https://developer.chrome.com/docs/webstore/user-data/).

---

## Назначение расширения (single purpose)

**AutoTest Recorder & Player** — инструмент для записи и воспроизведения сценариев тестирования веб-страниц в браузере пользователя: запись действий, визуальный редактор тестов, воспроизведение с проверками, логами и отчётами. Расширение не предназначено для сбора данных с сайтов в рекламных или иных целях, не связанных с тестированием.

---

## Какие данные куда передаются

| Категория | Поведение |
|-----------|-----------|
| **Серверы разработчика** | Расширение **не отправляет** содержимое ваших тестов, пароли сайтов и содержимое страниц на обязательный централизованный сервер только из‑за установки. Сетевые запросы к внешним адресам возможны только там, где вы явно задаёте URL (например, шаги API, открытие страниц в сценарии) или где включена опциональная функция, которая документирована в интерфейсе. |
| **Локальное хранилище** | Тесты, настройки, журналы прогонов и связанные данные хранятся **локально** в браузере через `chrome.storage` и при необходимости экспортируются **по вашему действию** (файлы в папку «Загрузки» и т.п.). |
| **Сторонние аналитики** | Встроенной передачи данных в рекламные или аналитические сети «по умолчанию» нет; при появлении таких опций они должны быть отключаемыми и описаны в интерфейсе и в этом документе. |

Уточните в форме магазина формулировку под вашу сборку (например, если подключаете облако или телеметрию): главное — **не противоречить** реальному коду.

## Доступ ко всем сайтам (`<all_urls>` / host permissions)

**Зачем нужен:** сценарии тестирования выполняются на **страницах по вашему выбору** — на внутренних стендах, localhost, SaaS и т.д. Заранее перечислить все домены невозможно.

**Как используется:** контент-скрипты и часть API работают только в контексте вкладок, где вы **запускаете запись или воспроизведение** (и связанных с этим функций). Расширение не «обходит» ваши действия для скрытого обхода политик сайта; оно реализует заявленные функции автоматизации тестов.

**Текст для формы (можно адаптировать):**  
*«Host permission &lt;all_urls&gt; нужен, чтобы записывать и воспроизводить тесты на любых URL, которые пользователь открывает для проверки своих приложений (включая корпоративные и локальные адреса). Список сайтов заранее неизвестен.»*

## Разрешения из `manifest.json` — кратко и по делу

Ниже формулировки, которые можно переносить в **описание для проверки** (justification) и в **подробное описание** в консоли разработчика.

### `debugger`

**Зачем:** подключение к [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/) в выбранной вкладке для функций, которые иначе недоступны из обычного DOM API — в частности **полноразмерный скриншот страницы** (расчёт размеров через `Page.getLayoutMetrics`, команды `Page.*`). Подключение **временное**: attach → команды → detach.

**Важно для пользователя:** одновременно с расширением нельзя держать открытыми штатные DevTools на той же вкладке для этой операции — это ограничение Chrome.

**Текст для формы:**  
*«Permission `debugger` используется только для съёмки полноразмерного скриншота через DevTools Protocol по запросу пользователя (шаг/команда в тесте). Не используется для удалённого управления браузером третьими лицами.»*

---

### `tabCapture`

**Зачем:** получение **идентификатора медиапотока вкладки** (`chrome.tabCapture.getMediaStreamId`) для **записи видео прогона теста** в файл (совместно с документом `offscreen` и пользовательскими настройками сохранения). Это опциональная функция записи экрана вкладки в рамках теста.

**Текст для формы:**  
*«`tabCapture` нужен для записи видео воспроизведения теста с выбранной вкладки в файл по инициативе пользователя (отчёты, демонстрация багов).»*

---

### `webRequest`

**Зачем:** при **включённом мониторинге сети** в рамках расширения собираются **метаданные запросов** во вкладке: URL, метод, тип, время, код ответа, ошибки. Это нужно для отображения в отчётах, анализа производительности и проверок, связанных с сетью. **Тело запросов и ответов не сохраняется** в показанной логике фона — только сведения о событиях запроса (см. реализацию в service worker).

**Текст для формы:**  
*«`webRequest` используется для мониторинга HTTP-запросов вкладки (метаданные: URL, статус, время) при включённой функции сетевого мониторинга; не для модификации трафика в рекламных целях.»*

---

### `offscreen`

**Зачем:** создание **offscreen document** с причиной `USER_MEDIA` для обработки медиапотока при **записи видео** прогона (связка с `tabCapture`).

**Текст для формы:**  
*«`offscreen` используется для записи видео прогона теста в фоновом документе согласно требованиям Manifest V3.»*

---

### `storage`

**Зачем:** локальное хранение тестов, настроек расширения, кэшей и журналов прогонов.

---

### `activeTab`, `scripting`, `tabs`

**Зачем:** доступ к **активной вкладке** при действии пользователя; **внедрение скриптов** для записи/воспроизведения; перечисление и переключение вкладок для сценариев с несколькими вкладками, навигацией и управлением окнами теста.

---

### `downloads`

**Зачем:** сохранение **экспортируемых файлов** (отчёты, экспорт тестов, видео, скриншоты и т.д.) в папку загрузок по команде пользователя; при необходимости — управление объектами загрузок, созданных расширением.

---

### `windows`

**Зачем:** открытие окон расширения (редактор, полноэкранный режим, вспомогательные окна), получение текущего окна, закрытие служебных окон по логике UI.

---

### `clipboardRead` / `clipboardWrite`

**Зачем:** шаги сценария и UI, связанные с **копированием и вставкой** (например, значения для полей, копирование селекторов в буфер обмена). Использование соответствует действиям пользователя в контексте тестирования.

---

### Пользовательский JavaScript в шагах теста

В сценариях может выполняться **код, введённый пользователем** в редакторе (шаги с произвольным JavaScript для проверок и автоматизации). Выполнение происходит **локально в расширении** в рамках воспроизведения теста, а не загрузка произвольного кода с внешних серверов. Это следует явно указать в описании для ревьюеров:

**Текст для формы:**  
*«Произвольный JavaScript в шагах теста выполняется только из сценариев, созданных или одобренных пользователем, локально при прогоне; расширение не подгружает исполняемый код с удалённых URL для обхода политик магазина.»*

## Рекомендации для карточки в Chrome Web Store

1. В **кратком описании** не обещайте функций, которых нет; укажите, что это инструмент **QA / автоматизации тестов**.
2. В **подробном описании** перечислите ключевые возможности и укажите, что для работы на сайтах пользователя нужен **доступ к данным на всех сайтах** — с формулировкой выше.
3. В поле **политики конфиденциальности** укажите **публичный URL** этой страницы (после публикации в репозитории GitHub) или выложите тот же текст на отдельной странице.
4. Если модерация задаёт вопросы по `debugger` / `webRequest` / `&lt;all_urls&gt;` — отвесьте ссылкой на этот файл и процитируйте соответствующий абзац.

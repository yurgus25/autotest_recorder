# Аналитика Производительности - Полное Руководство v0.9.4.8

## 🚀 Быстрый Старт

### 1. Включение Анализа Производительности
1. Откройте тест в редакторе
2. Нажмите **+ Вставить Шаг**
3. Выберите **Анализ → Производительность**
4. Сохраните тест

### 2. Запуск Теста
- Нажмите **▶️ Полный Прогон** или **⚡ Оптимизированный**
- Данные производительности собираются автоматически
- Метрики отслеживаются на каждом шаге

### 3. Просмотр Результатов
- Нажмите кнопку **📊 Посмотреть Отчёт**
- Dashboard открывается в новой вкладке
- Просмотрите метрики, бюджеты, рекомендации

## 📊 Обзор Возможностей

### Основные Метрики (Собираются Автоматически)
- ✅ **Web Vitals**: LCP, CLS, INP, TTFB
- ✅ **Navigation Timing**: DNS, TCP, Request, Response, DOM, Load
- ✅ **Resource Timing**: Размер, длительность на ресурс
- ✅ **Step Timing**: Длительность, разбивка Plugin vs Page
- ✅ **Long Tasks**: Задачи блокирующие UI >50мс
- ✅ **Memory**: Размер heap, обнаружение утечек
- ✅ **DOM**: Размер, глубина, количество элементов

### Форматы Экспорта
- **📥 JSON**: Полный экспорт данных
  - Полный набор данных
  - Совместим с baseline
  - Готов для анализа

- **📊 HAR**: Формат HTTP Archive
  - Импорт в Chrome DevTools
  - Загрузка в WebPageTest
  - Стандартный waterfall анализ

- **📊 CSV**: Анализ в Excel/Sheets
  - 4 типа: Шаги, Ресурсы, Long Tasks, Сводка
  - Готов для pivot таблиц
  - Удобен для графиков

### Бюджеты Производительности
**Нажмите кнопку ⚙️ Бюджеты для настройки**

**Пресеты**:
- 🔴 **Строгий**: Высокопроизводительные приложения (LCP <1.5s)
- 🟡 **Умеренный**: Сбалансированный (LCP <2.5s) - По умолчанию
- 🟢 **Мягкий**: Сложные приложения (LCP <4s)
- ⚙️ **Свой**: Ручная настройка

**Категории**:
1. **Бюджеты Web Vitals**
   - LCP (Largest Contentful Paint)
   - CLS (Cumulative Layout Shift)
   - INP (Interaction to Next Paint)
   - TTFB (Time to First Byte)

2. **Бюджеты Производительности Теста**
   - Общая длительность теста
   - Средняя длительность шага
   - Макс количество Long Tasks
   - Общее время блокировки

3. **Бюджеты Ресурсов**
   - Общее количество ресурсов
   - Общий размер (MB)
   - Макс размер скрипта (KB)
   - Макс размер изображения (KB)

**Валидация**:
- Автоматически после каждого теста
- Показывает нарушения в dashboard
- Важность: Критично / Предупреждение / Незначительно
- Готов для CI/CD (exit codes)

### Расширенный Анализ

**Оценка Производительности (0-100)**:
- Общий рейтинг производительности
- Рейтинги: Отлично (90+), Хорошо (75-89), Требует Улучшения (50-74), Плохо (<50)
- Автоматический расчёт на основе метрик

**Обнаружение Регрессий**:
- Автоматическое сравнение с сохранённым baseline
- Порог 10% (настраивается)
- Выделяет падение производительности
- Показывает точный процент изменения

**Обнаружение Узких Мест**:
- Медленные шаги (>2x среднего)
- Большие ресурсы (>500KB)
- Long tasks (>100ms)
- Плохие Web Vitals
- Высокая сложность DOM

**Движок Рекомендаций**:
- Практичные предложения по оптимизации
- Приоритет (Критично → Высоко → Средне → Низко)
- Контекстно-зависимые на основе реальных проблем
- Пошаговые исправления

### Визуализация Timeline

**Возможности**:
- Визуальный график по шагам
- Plugin overhead vs Page delay
- Интерактивные подсказки
- Сводная статистика

**Режим Сравнения**:
- Overlay текущий vs baseline
- Цветовая кодировка регрессий (красный = медленнее, зелёный = быстрее)
- Таблица сравнения с разницей
- Процентные изменения

### Отслеживание Long Tasks

**Автоматическое Обнаружение**:
- Задачи блокирующие main thread >50мс
- Attribution (какой скрипт)
- Привязка к шагу
- Классификация важности

**Визуализация**:
- График timeline по шагам
- Топ 10 long tasks
- Критично (>100ms) vs Предупреждение (50-100ms)
- Идентификация источника

**Метрики**:
- Общее количество long tasks
- Количество критичных задач
- Общее время блокировки
- Самая долгая задача
- Средняя длительность

### Профилирование Памяти

**Отслеживание на Каждом Шаге**:
- Используемый JS Heap
- Общий JS Heap
- Лимит Heap
- Процент использования

**Обнаружение Утечек**:
- Автоматический алгоритм
- Критерии: >1MB/шаг или >10MB всего
- Анализ паттерна роста
- Важность: Критично / Предупреждение / Инфо

**Экспорт**:
- Снимки памяти в JSON
- CSV экспорт для графиков
- Анализ трендов

## 🎯 Типичные Сценарии

### Сценарий 1: Мониторинг Производительности
```
1. Создать тест с анализом производительности
2. Установить бюджеты (кнопка ⚙️ Бюджеты)
3. Регулярно запускать тест
4. Проверять нарушения
5. Исправлять критичные проблемы
6. Перетестировать и проверить
```

### Сценарий 2: Сравнение с Baseline
```
1. Запустить тест на стабильной версии
2. Сохранить как baseline (💾 Сохранить Baseline)
3. Внести изменения в код
4. Запустить тест снова
5. Проверить обнаружение регрессий
6. Сравнить графики timeline
7. Экспортировать отчёт с различиями
```

### Сценарий 3: Оптимизация
```
1. Запустить тест для установления baseline
2. Проверить раздел узких мест
3. Изучить рекомендации
4. Применить оптимизации
5. Перетестировать
6. Сравнить оценку производительности
7. Итерировать до оценки >90
```

### Сценарий 4: Интеграция в CI/CD
```
1. Настроить строгие бюджеты
2. Экспортировать JSON в CI pipeline
3. Проверить нарушения бюджета
4. Провалить сборку при критичных проблемах
5. Сохранять отчёты как артефакты
6. Отслеживать тренды во времени
```

## 📈 Справка по Метрикам

### Пороги Web Vitals

**LCP (Largest Contentful Paint)**:
- ✅ Хорошо: ≤ 2500ms
- ⚠️ Требует Улучшения: 2500-4000ms
- ❌ Плохо: > 4000ms

**CLS (Cumulative Layout Shift)**:
- ✅ Хорошо: ≤ 0.1
- ⚠️ Требует Улучшения: 0.1-0.25
- ❌ Плохо: > 0.25

**INP (Interaction to Next Paint)**:
- ✅ Хорошо: ≤ 200ms
- ⚠️ Требует Улучшения: 200-500ms
- ❌ Плохо: > 500ms

**TTFB (Time to First Byte)**:
- ✅ Хорошо: ≤ 800ms
- ⚠️ Требует Улучшения: 800-1800ms
- ❌ Плохо: > 1800ms

### Классификация Long Tasks
- **Нормально**: <50ms (не отслеживается)
- **Предупреждение**: 50-100ms (влияет на UX)
- **Критично**: >100ms (значительно блокирует UI)

### Критерии Утечки Памяти
- Средний рост >1MB на шаг
- Общий рост >10MB
- Рост в >70% шагов

## 🔧 Устранение Проблем

### Проблема: Данные производительности не собираются
**Решение**: Убедитесь что тест содержит шаг `analysis-performance` и был успешно выполнен

### Проблема: Web Vitals показывают null/0
**Решение**: Используйте браузер Chrome/Edge. Firefox/Safari имеют ограниченную поддержку API

### Проблема: Нарушения бюджета не показываются
**Решение**: Нажмите ⚙️ Бюджеты для настройки бюджетов сначала

### Проблема: Режим сравнения пустой
**Решение**: Сначала сохраните baseline (кнопка 💾 Сохранить Baseline)

### Проблема: Кнопки экспорта не работают
**Решение**: Убедитесь что данные производительности загружены. Проверьте консоль браузера на ошибки

### Проблема: Секция Long tasks скрыта
**Решение**: Long tasks появляются только если обнаружены задачи >50ms

### Проблема: Данные памяти недоступны
**Решение**: Функция только для Chrome. Включите в chrome://flags при необходимости

- Измеряйте перед оптимизацией (baseline)
- Одно изменение за раз
- Проверяйте эффект повторным тестом
- Документируйте что сработало
- Сначала фокус на Критичных проблемах

- HAR для визуализации waterfall

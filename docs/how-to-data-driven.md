# Data-driven прогоны (CSV): как подготовить тест и выполнить

Черновик для внутренней документации и будущего сайта (рядом с `how-to-test-visual-regression-lite.md`).

## Идея

Один и тот же сценарий (набор шагов) выполняется **много раз** — по **одной строке таблицы** за итерацию. Значения из строки попадают в **переменные теста**; в шагах подставляются в URL, поля ввода, ожидаемый текст и т.д.

Оркестрация: **background** (`dataDrivenState`, очередь после `TEST_COMPLETED`), запуск из **редактора** (`editor-data-driven.js`, модальное окно CSV).

## Лимиты

- Не более **50 строк данных за один прогон** (`TestEditor.DATA_DRIVEN_MAX_ROWS` в `editor/editor-data-driven.js`; в интерфейсе то же число).
- Первая строка CSV — **заголовки столбцов**, далее — только строки данных.

## Формат CSV

1. **Первая строка** — имена переменных (заголовки колонок), без пустых ячеек в шапке.  
   Пример:
   ```text
   email,password,expectedTitle
   user1@example.com,secret1,Welcome
   user2@example.com,secret2,Dashboard
   ```
2. Разделитель — **запятая**. Поддерживаются **кавычки** и экранирование `""` внутри ячеек (см. `TestEditor.parseDataDrivenCsv`).
3. Имена колонок лучше делать **латиницей**, `буквы/цифры/_` (так проще согласовать с проверкой переменных в редакторе).

## Как связать CSV со шагами теста

Фон при каждой итерации **сливает строку** в `test.variables` (как `groupContext`), плеер при старте кладёт значения в **`userVariables`** (`content/player-core.js`, `playTest` / `resumePlayback`).

### Синтаксис подстановки в плеере

В строковых полях шагов (значение ввода, URL навигации, ожидаемый текст, тело API как строка и т.п.) плеер подставляет переменные через **`${имяПеременной}`**, где **`имяПеременной` совпадает с заголовком столбца** CSV.

Примеры:

- Ввод логина: значение поля `user@mail.com` заменить на `${email}`.
- Пароль: `${password}`.
- Навигация или URL: при необходимости `https://app.example.com/login?user=${email}`.

Реализация: `TestPlayer.substituteVariables` / `processVariables` в `content/player-core.js` (шаблон **`${…}`**).

В интерфейсе редактора и в подсказках к data-driven часто фигурирует формат **`{var:email}`**. Он используется в **части** сценариев (например, разбор условий, отдельные места в API). Если подстановка в конкретном шаге не срабатывает, для значений шагов надёжнее ориентироваться на **`${имя_столбца}`** — это основной путь для `processVariables` в большинстве обработчиков.

### Переменные в редакторе (вкладка Variables)

- Если в шагах встречается **`{var:имя}`**, редактор при запуске может проверить, что в **`test.variables`** заданы значения по умолчанию (`checkRequiredVariables` в `editor/editor-ui-helpers.js`).  
- Для **data-driven** значения всё равно **перезаписываются строкой CSV** на каждой итерации; дефолты в редакторе помогают не получать предупреждение «не хватает переменных» и дают значения для обычного одиночного прогона без CSV.

## Подготовка сценария

1. Запишите или соберите сценарий так, как для одного пользователя/набора данных.
2. Замените фиксированные данные на **`${column}`**, где `column` — заголовок из будущего CSV.
3. Убедитесь, что стартовый URL и шаги не зависят от состояния, которое не сбрасывается между итерациями (или добавьте шаги «выйти / очистить / заново открыть форму»).
4. При необходимости объявите переменные в редакторе с тестовыми значениями для проверки сценария **без** CSV.

## Запуск data-driven из редактора

1. Откройте тест в **`editor.html`** / **`editor_ru.html`**.
2. Нажмите кнопку **Data-driven (CSV)** (рядом с обычным запуском).
3. Вставьте CSV в текстовое поле.
4. **Предпросмотр** — проверка разбора и таблица колонок/строк.
5. Запуск:
   - **Запуск (оптимизированный)** — фактический режим может быть `optimized` или `full`, если оптимизация недоступна (см. код кнопки).
   - **Запуск (полный)** — режим **`full`**.
6. После старта показывается alert с числом итераций; дальше прогон идёт во вкладке(ах) как обычный `PLAY_TEST`, но фон ставит в очередь следующие строки после каждого **`TEST_COMPLETED`**.

## Что происходит в фоне (кратко)

- При первом `PLAY_TEST` с **`dataDrivenStart: true`** и **`dataDrivenRows`**: создаётся **`dataDrivenState`**, первая строка уходит в **`groupContext`**, в payload добавляются **`dataDrivenRowIndex` / `dataDrivenRowTotal`**.
- После завершения теста **`TEST_COMPLETED`**: если очередь не пуста, вызывается следующий **`handlePlayTest`** с **`_fromDataDrivenQueue: true`** и **`groupContext`** из следующей строки.
- После последней строки рассылается **`DATA_DRIVEN_RUN_COMPLETED`** с сводкой (все строки / сколько упало).

Код: `background/background-sw.js` (`handlePlayTest`, `dataDrivenState`), `background/message-handlers-sw.js` (ветка **`TEST_COMPLETED`** для data-driven).

## Результат и отчёт

- Редактор подписан на **`DATA_DRIVEN_RUN_COMPLETED`**: тост об успехе или о том, что часть строк упала (`editor/editor-core.js`).
- Сохраняется **`lastDataDrivenReport`** для **экспорта CSV**:
  - кнопки **«Экспорт отчёта (CSV)»** в шапке редактора и в модалке data-driven активируются после успешного завершения серии для **этого же** теста;
  - в отчёте: `PASS`/`FAIL` по строке, ошибка, длительность, шаги, плюс колонки исходных данных.

Код отчёта: `TestEditor.buildDataDrivenReportCsv` в `editor/editor-data-driven.js`.

## Типичные проблемы

| Симптом | Что проверить |
|--------|----------------|
| Данные не подставляются | В шагах для значений используйте **`${имяСтолбца}`**; имя совпадает с заголовком CSV (регистр). |
| «Не хватает переменных» при старте | Задайте переменные в редакторе или замените в шагах на синтаксис, который редактор не требует как `{var:…}`, либо добавьте дефолты в `test.variables`. |
| Слишком много строк | Разбейте CSV на части по ≤ 50 строк или дождитесь повышения лимита (в UI указан Premium как направление). |
| Вторая итерация ломается | Сценарий должен возвращать приложение в состояние, готовое к следующему набору данных (выход, обновление страницы, очистка сессии). |
